# Agentic Workflows (`gh-aw`) Router & Operational Guide

Use this skill when designing, creating, updating, compiling, debugging, or upgrading GitHub Agentic Workflows (`.github/aw/`, `.github/workflows/*.md`, and `.github/workflows/*.lock.yml`) across `carlkidcrypto` repositories.

This skill is a dispatcher and operational reference: identify the task type, apply the domain, security, and network rules, and follow the compilation and diagnostic procedures below.

## 2. Compiling & Locking Workflows

When editing `gh-aw` workflows (`.github/workflows/*.md`):
- **Never edit `*.lock.yml` files manually**: They are compiled outputs generated by `gh-aw`.
- **Always recompile after changes**: Run `gh aw compile` (or `gh aw compile .github/workflows/<workflow>.md`) in the repository root to regenerate `.lock.yml`, `agentics-maintenance.yml`, and `.github/aw/actions-lock.json` with 0 errors and 0 warnings.
- **Commit both**: Always commit both the `.md` workflow definition and the generated `.lock.yml` (using targeted `git add <files>`, never `git add -A`).
- **Lockfile Merge/Rebase Conflicts**: When rebasing or merging `main` creates conflicts in generated files (`.github/aw/actions-lock.json`, `*.lock.yml`), accept `origin/main` for the generated files and re-run `gh aw compile` instead of hand-merging lockfiles.

## 3. Network Configuration & Allowed Domains

- **Explicit Domain Whitelisting (`api.github.com`)**: When configuring GitHub REST API access in workflow network frontmatter (`network.allowed`), **always explicitly specify `api.github.com` instead of the `agy` preset bundle**. This keeps firewall rules transparent and self-documenting across all repositories:
  ```yaml
  network:
    allowed: [defaults, github, python, api.github.com]
  ```
- **Preset Nuances**:
  - The `github` preset only includes git/web endpoints (`github.com`, `raw.githubusercontent.com`, `codeload.github.com`). It does **not** include `api.github.com`.
  - Any script or tool calling `https://api.github.com` (REST APIs, commits, releases, container tags) requires `api.github.com` in `network.allowed`.
- **Language Package Ecosystem Presets**: When workflows run build tools, package managers, or fallback installers in bash (`go install`, `pip install`, `npm`), declare the corresponding ecosystem preset in `network.allowed`:
  - `go`: `proxy.golang.org`, `storage.googleapis.com`, `sum.golang.org`, `go.dev`, `golang.org`
  - `python`: `pypi.org`, `files.pythonhosted.org`
  - `npm`: `registry.npmjs.org`
  ```yaml
  network:
    allowed: [defaults, github, go, api.github.com]
  ```

## 4. Diagnosing Agentic Workflow Firewall (AWF) SSL Failures

The GitHub Agentic Workflow Firewall runs an egress proxy (Squid) with a strict default-deny policy for all unlisted domains.

- **Symptoms**: Outbound requests fail with self-signed TLS certificate errors:
  - Python (`urllib` / `requests` / `httpx`):
    ```text
    urllib.error.URLError: <urlopen error [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain (_ssl.c:1000)>
    ```
  - Node.js: `DEPTH_ZERO_SELF_SIGNED_CERT` or `self-signed certificate in certificate chain`
  - `curl`: `curl: (60) SSL certificate problem: self-signed certificate`
  - Agent output: The agent fails to complete the task and emits a `report_incomplete` safe output.
- **Root Cause**: An outbound connection targeted a host not listed in `network.allowed`. Squid intercepted the connection and returned a proxy error page with a self-signed certificate.
- **Resolution**:
  1. Inspect the stack trace to identify the destination host (e.g. `api.github.com`, `registry.hub.docker.com`).
  2. Add the host (or ecosystem preset) to `network.allowed` in the workflow `.md` frontmatter.
  3. Recompile via `gh aw compile`.

## 5. Scheduled Workflow Deduplication (`skip-if-match`)

Workflows triggered via `on: schedule:` (cron) that open PRs or issues must configure `skip-if-match` under `on:` to avoid redundant runs and duplicate PRs when an open PR already exists:

```yaml
on:
  schedule:
    - cron: "0 6 * * 1"
  skip-if-match:
    pull-requests:
      labels: ["<workflow-label>"]
      state: open
```

## 6. Authentication & Token Conventions

- **Dual Token Fallback**: Helper scripts invoked inside workflows should check both `GITHUB_TOKEN` and `GH_TOKEN`:
  ```python
  token = os.environ.get("GITHUB_TOKEN") or os.environ.get("GH_TOKEN")
  ```
- **Frontmatter Permissions**: Grant only the permissions required by the workflow and its active GitHub MCP toolsets:
  ```yaml
  permissions:
    contents: write
    pull-requests: write
    issues: write
  ```

## 7. Public Intake & Bug Triage Workflows (`min-integrity: none`)

When an agentic workflow is triggered by public events (`issues: [opened, edited]`, community PRs):
- **Symptom**: `github/issue_read` fails with:
  `Resource 'issue:...' has lower integrity than agent requires. The agent cannot read data with integrity below "approved".`
- **Cause**: In public repositories, `gh-aw` defaults to `min-integrity: approved`, causing the MCP gateway DIFC guard to block reading untrusted community issues (`none:public`).
- **Resolution**:
  ```yaml
  tools:
    bash: false
    cli-proxy: false
    github:
      min-integrity: none
  ```
  - In strict mode, `min-integrity: none` requires `tools.bash: false` and `tools.cli-proxy: false` so untrusted input cannot execute unconstrained shell commands.
  - Ensure all permissions required by active GitHub MCP toolsets (e.g. `pull-requests: read` when `pull_requests` toolset is enabled) are granted in frontmatter `permissions:` to avoid compiler warnings.

## 8. Unattended Tooling & Binary Downloads (`--allow-all-tools`)

When workflows run with `engine.id: copilot` and install CLI binaries or download tools via `curl` or scripts during prompt execution:
- **Symptom**: Shell URL downloads fail with:
  `Permission denied because no interactive user response was available. Retry in an interactive session so the user can approve it, or try an alternative that does not require this permission.`
  In `events.jsonl`, `permission.requested` with `kind: "url"` receives `denied-no-approval-rule-and-could-not-request-from-user`.
- **Cause**: Copilot CLI in unattended mode (`--no-ask-user`) blocks shell-invoked URL downloads unless `--allow-all-tools` is configured.
- **Resolution**:
  ```yaml
  engine:
    id: copilot
    args: ["--allow-all-tools"]
  ```

## 9. Inline Skills & Safe Outputs Allowed-Files Protection

Workflows that define inline skills (`## skill: <name>`) restore those skills dynamically into the runner workspace at `.github/skills/<name>/SKILL.md`.

- **Symptom**: Safe output step `create_pull_request` fails with:
  `create_pull_request: Cannot create pull request: patch modifies files outside the allowed-files list (.github/skills/.../SKILL.md).`
- **Cause**: The restored inline skill is an untracked file in the runner workspace. Blanket staging (`git add -A` or `git add .`) includes it in the patch, which violates `safe-outputs.create-pull-request.allowed-files`.
- **Resolution**:
  1. **`.gitignore`**: Exclude dynamically restored skills while preserving tracked skills:
     ```gitignore
     # Dynamically extracted gh-aw inline skills
     /.github/skills/*
     !/.github/skills/agentic-workflows/
     ```
  2. **Workflow Prompt Guidelines**: In `Hard Requirements` and `Pull Request Output`, instruct agents to stage only modified target files (`git add <file>`) and explicitly prohibit blanket staging (`git add -A` / `git add .`).
  3. Recompile with `gh aw compile`.

## 10. Auditing & Debugging Workflow Runs

To investigate any failed or incomplete workflow run:
1. Run `gh aw audit <run-id>` inside the repository.
2. Inspect `agent_output.json` for reason codes (`report_incomplete`, `missing_data`, etc.).
3. Inspect `sandbox/agent/logs/copilot-session-state/<session-id>/events.jsonl` for exact `tool.execution_start`, `permission.requested`, and `permission.completed` entries.
4. Compare against downloaded successful baselines (`baseline-<run-id>/`).
5. For suspected Copilot credit / HTTP 429 rate-limit failures, check `gh run view <run-id> --log-failed` for `ai_credits_rate_limit_error`, `errorCodes=[429]`, or `errorTypes=["rate_limit"]`. To triage and close fleet-wide `[aw] ...: hit engine rate limit (HTTP 429)` issues, use `repo-fleet-ops/scripts/close_aw_rate_limit_issues.py --verify-logs` (dry-run by default; pass `--apply` to close as `not_planned`).
